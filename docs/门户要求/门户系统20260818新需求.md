## 方案调整

不绑角色，绑权限码。角色会增删改名且跨系统复用（`admin` 是全公司共享的），
权限码稳定且按资源划分。

应用配置加一个字段，不要建「用户-应用」授权表，RBAC 是唯一事实源：

  app: { id, name, icon, url, requires: string[] }

  def visible(app, user_permissions):
      if not app.requires:            # 空数组 = 所有登录用户可见
          return True
      return any(p == r or p.split(":")[0] == r
                 for p in user_permissions for r in app.requires)

requires 元素可以是完整权限码，也可以是系统前缀，命中任一即可见。
现阶段多数码还是无前缀老写法，所以要列完整码；将来码补上前缀，缩成 ["<system>"] 即可，代码不用改。
通配规则：`<system>:*` 表示该系统全部权限，只有第一段能带 `*`。持有 `*` 视为可见全部应用。

示例：
  { id:"pm",    requires:["read:sku","read:spu","read:csku","read:categories"] }
  { id:"tools", requires:[] }     // 工具类应用，RBAC 侧无需任何配置

requires 设为必填、默认 []、不允许 null——否则「忘了填」和「故意公开」在数据里没法区分。
新建应用时强制二选一：勾权限码，或勾「所有登录用户可见」。

## 一个现状约束

RBAC 里大量角色（member 201 人、普通员工等）目前权限数为 0，严格按码过滤会导致
多数人登录后看不到任何应用。所以 requires:[] 这条路径必须支持，让门户能先上线。
