## 二、任务一：可见性改配权限码 —— 如何满足

需求原文的每一条要求，对应实现如下：

| 需求要求 | 实现 | 位置 |
|---|---|---|
| 调用 `GET /api/service/catalog`，Service Token 双头，服务端缓存带 ETag | 目录客户端：TTL 10 分钟；过期后带 `If-None-Match` 回源，304 只续期 | `app/rbac_catalog.py` |
| 接口偶发 502，要重试 + 旧缓存兜底 | 非 200/异常重试一次；仍失败返回旧缓存并记 WARNING；从未成功过才报 503 | 同上 |
| 候选项可按 system 分组展示 | 后台"可见权限"选择器按 system 分组，`system=null` 归"未分组"，另有手动输入框 | `frontend/admin.html` |
| 用户维度仍用 by-jwt 接口取 `permissions[]` | 认证层不变，取返回的裸码数组参与匹配 | `app/auth.py` |
| 应用加 `requires: string[]`，不建用户-应用授权表 | `modules.requires TEXT[]`，RBAC 为唯一事实源；公告同字段同规则 | `migrations/002、003` |
| 空数组 = 所有登录用户可见（大量角色权限数为 0，必须支持） | `requires_visible()` 第一条分支 | `app/main.py` |
| 完整码或系统前缀命中任一即可见 | `perm == req` 或 `perm.split(":")[0] == req` | 同上 |
| `<system>:*` 表示该系统全部权限，只有第一段能带 `*` | 用户侧与应用侧双向支持；`*` 出现在其他位置的码被校验拒绝（422） | 同上 |
| 持有 `*` 视为可见全部 | 第二条分支直接放行 | 同上 |
| `requires` 必填、默认 `[]`、不允许 null | Pydantic 模型 `list[str]` 默认空列表，null 被拒 | 同上 |
| 新建应用强制二选一：勾权限码，或勾"所有登录用户可见" | 弹窗 radio 二选一；选了"按权限码"却未勾码会被拦下 | `frontend/admin.html` |

补充两点：

- **过滤在后端做**。`GET /api/modules` 用当前用户的 `permissions[]` 过滤后才返回，前端隐藏只是体验优化，不是安全边界。
- **无前缀老码兼容**。需求指出现阶段多数码是无前缀写法，实现按"完整码相等"处理；将来码补上前缀后，应用配置缩成 `["<system>"]` 即可，代码不用改。08-19 用 Service Token 实测真实目录：5 个系统、51 个权限码、69 个角色，含无前缀码与 `system=null` 码，前端分组与匹配均正常。

从角色制到权限码的迁移分两步走：`002` 加新列、保留旧列，只把"admin 角色可见"自动翻译为 `admin:*`；需求方确认公告同改、门禁同改后，`003` 删旧列与角色池表。中间版本可回滚，不丢数据。

## 三、任务二：PostgreSQL + admin 管后台 —— 如何满足

- **PostgreSQL**：psycopg3 连接池；表结构用 `migrations/*.sql` 版本化管理，启动时按序执行并在 `schema_migrations` 记账，失败整体回滚、拒绝启动。四张业务表：应用模块、用户收藏、横幅公告、操作审计。
- **admin 才能进后台**：`/api/admin/*` 全部接口统一门禁 `require_permission("portal:manage:console")`。admin 角色在 RBAC 目录里持有 `*`，天然通过；无权限用户访问返回 403。
- **一处口径说明**：门禁判的是权限码而不是角色名。这样做与任务一"不绑角色"的思路一致，效果上 admin 照常能进；额外的好处是该码在 RBAC 登记后，可以把"管门户"单独授给非超管角色。如需求方只认 admin 角色，改一行判定即可。

## 七、待办与可优化之处

**需公司侧配合（服务器上线前提）**

1. RBAC 登记权限码 `portal:manage:console`，并确认 admin 角色分配。
2. 域名 `portal.zestrade.com` 接入 oauth2-proxy（Keycloak）。
3. Keycloak Client 的 "Valid post logout redirect URIs" 加入 `https://portal.zestrade.com/*`。
4. 服务器 `.env`：填 RBAC 凭证、`OAUTH2_PROXY_SIGN_OUT_URL`、生产库连接串，`AUTH_BYPASS=false`。

**代码侧可优化（不影响当前需求）**

1. 权限缓存为进程内存，多 worker 部署时各自独立；若不能接受 5 分钟延迟，换 Redis。
2. 本机演示库内仍有开发期测试数据（3 条过期公告、审计流水），正式演示前可在后台清理。
3. 测试客户端依赖的 Starlette 接口将弃用，届时需在开发依赖中加 `httpx2`。
4. 后台门禁若需求方要求严格只认 admin 角色，可增加角色名判定作为第二道条件。
5. 公告与应用的 `requires` 编辑目前各一个选择器实例，若后续再加可见性对象，可抽成公共组件。
